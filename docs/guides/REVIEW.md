# 生产评审协议

评审的目的不是"看起来做完了"，而是**能拿出证据说明它明天还能用**。任何一项没有证据，按未通过处理。

## 谁能评审

独立子代理（换模型、只读仓库与证据、不参与实现）。评审者不改代码，只出结论与整改项。

## 结论只有两种

- **PASS**：该条目下的验收证据齐全，且能复现。
- **FAIL**：缺证据、证据不成立、或复现失败。必须列出整改项。

同一条目连续两次 FAIL，升级到所有者决策，不许自行降低标准。

## 证据的最低要求

| 类型 | 合格证据 | 不合格 |
|---|---|---|
| 代码修复 | 提交哈希 + 触发条件的测试或日志 + 修复后同条件复现结果 | "已修改"、只贴 diff |
| 性能 | 修改前后同机同数据的对照数字（至少 3 次取中位） | 单次最好值、换环境对比 |
| 语音链路 | 网关日志行 + 设备端事件日志 + 时间戳能对上 | 只贴服务端日志 |
| 部署 | 目标系统上的 `systemctl status` + 端口监听 + 一次真实请求 | macOS 上跑通 |
| 备份 | 恢复演练记录（恢复后行数与 integrity_check） | 只看备份文件存在 |
| 安全 | 实际未授权的请求被拒（含命令与响应码） | 代码里有检查分支 |

## 条目与判据

### A 阻断上线

- **A1 24 小时真实长跑**：真实模型、真实语音入口，连续 24 小时；失败要能定位到原因；断供期间不得静默停摆。
- **A2 主备切换**：主站返回 402/429/超时时，自动切到已验合格的备用；切换过程对用户可感知（有一句说明），切回有记录。
- **A3 服务器部署**：目标 Linux 上从零安装到可对话，`systemctl status` 健康，重启后自恢复。
- **A4 Linux 侧能力**：技能执行、通知通道、Mac 数据桥接在服务器上可用，或明确标注为"仅 Mac 可用"。
- **A5 幂等**：取消后不再产生副作用；崩溃重启不重复发同一条消息/命令。证据是故障注入测试，不是设计文档。
- **A6 记忆改造**：内心循环的记忆召回改造按原门槛重新验收，不许事后降低门槛。
- **A7 三端闭环**：iPhone / Watch / Mac 各自完成"说话→回答→打断→续问"的真机记录。

### B 功能接线
每条要求：入口存在、被主循环调用（有调用点证据）、有一次真实运行记录。

### C 已知缺陷
每条要求：缺陷不再复现（复现脚本 + 修复后输出）。

### D 验收欠账
- **D2 冻结版全量回归**：代码冻结后跑全量测试，失败项必须为 0 或有明确豁免理由；再由独立评审复核。

### E 安全运维
- **E1 凭据隔离**：模型子进程读不到明文 key（用 `/proc/<pid>/environ` 与文件系统证据证明）。
- **E2 入口安全**：公网不可直连网关；未带 token 的连接被拒（实际请求 + 状态码）。
- **E5 备份**：异地副本存在，且做过一次完整恢复演练。
- **E6 告警**：拔网、杀进程、塞满磁盘三种故障各触发一次真实告警到设备。

## 评审产出

写入 `docs/reports/REVIEW_<日期>.md`：

1. 结论表（条目 / PASS|FAIL / 证据指针）
2. 整改项清单（按阻断程度排序）
3. 本次评审未覆盖的范围（明确写出来，不许留白）
