- Phase: K0-A

## 目标

建立精确、可自动验证的 Task / Plan / Step / Attempt / Intent 契约与领域对象。保持领域层不依赖 SQLite。不得启用实际任务执行。

## 依据与开始前检查

读取 JARVIS_GOAL.md、Master Plan 的核心对象、状态机、Contract Pack、K0-002 验收与文档冻结门禁，全部 contracts/ 与 docs/adr/ 草案。核对 K0-001 测试、评审与 Git 证据。

## 允许范围

补充契约设计草案、领域验证对象、Schema 正反例、解析和一致性测试；建立 ADR 主题映射与冻结门禁追踪表。所有新设计保持 DRAFT，涉及核心安全语义的方案记录待审批，不自行批准。

## 禁止范围

不实现执行器、任务数据库、真实发布、恢复调度，不启用 K1-K4，不将草案标记 FROZEN，不改变现有安全不变量。

## 主要缺口

- Task / Step 转换的 Guard 是占位符，需逐条精确化。
- Plan / Step / Attempt 领域数据与关联还未形成完整 Schema。
- 同一 Step 多次 Attempt 复用同一 Intent 行，Operation Key 唯一不与此冲突。
- Reconciliation 需要合法 Observation / Decision 配对及重试前提。
- 路径约束、单文件限制、目录深度、UTF-8 名称、符号链接与特殊文件策略需机器契约。
- Snapshot Manifest 与最终 inventory 输出需明确区分和映射。
- 取消提交与发布启动间的并发线性化仍待方案和验证。
- Contract Pack 完全冻结门禁包含后续数据库、发布、竞态测试，需明确阶段性设计批准与整体冻结区别，不能自行绕过。
- Master Plan 建议 ADR 编号与现有编号主题不同，建立明确映射，保留原文件身份。

## 验收

- 契约文件可解析，状态集合唯一，转换表完整。
- 合法与非法 Schema 示例经过自动测试。
- 取消仲裁规则明确且符合 INV-010。
- Intent 与 Attempt 关系明确。
- 文件发布语义形成正式 ADR，并满足相应审批与验证。
- Python 领域对象与机器契约一致。
- Ruff、Pyright、pytest、安全审查、独立评审通过。

## 验收状态

NOT_VERIFIED；未满足审批或冻结前置时不得标记 DONE，不阻止安全的设计与测试工作。
