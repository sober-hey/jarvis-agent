# ADR-0009 一句话切分放在客户端，用可仿真的 UtteranceGate

状态：已实施（2026-10-21）
相关：`apps/mac/JarvisMac/Sources/JarvisIntegration/UtteranceGate.swift`、`apps/ios/.../AudioPrimitives.swift`

## 背景

原实现是固定门限 0.012 + 1.0 秒静音硬切，真实说话方式会打穿它：思考停顿超过 1 秒被切成两句、
小声说话进不来、嘈杂房间把底噪当人声、说完立刻补充被当成第二次提问。

## 决策

1. 切分放在**客户端**（只有设备知道实时音频与播放状态），网关只负责按轮处理。
2. 抽成纯逻辑 `UtteranceGate`，可离线仿真，用 16 种说话方式回归。
3. 参数对齐行业默认值（见 `docs/guides/VOICE.md` 第五节）。

## 关键规则

- 启动先 0.5 秒标定房间底噪，门限 = 底噪 × 2.0（下限 0.004），不写死音量。
- 结束静音分档：短句 1.4 s、常规 0.9 s、长独白 0.8 s。
- 判定结束后留 0.5 s 观察窗，期间再出声算同一句。
- 开口前保留 300 ms 预卷；不足 0.10 s 语音的片段不上传。

## 依据

| 来源 | 数值 |
|---|---|
| 豆包 `end_window_size` | 推荐 800–1000 ms |
| 豆包端到端 `end_smooth_window_ms` | 默认 1500 ms |
| 豆包语义 VAD | 句末 300 / 逗号 400 / 无法判定 700 ms |
| OpenAI Realtime `prefix_padding_ms` | 默认 300 ms |
| Google 连续对话 / Alexa follow-up | 约 8 s / 5–8 s（我们取 25 s） |

## 验证

`Tests/UtteranceSimulation` 覆盖：正常句、短回答、思考停顿 0.8/1.2/1.6/2.0 s、小声、
嘈杂、纯噪声、拖音、30 s 独白、说完补充、键盘敲击、噪声抬升等，16/16 通过。

## 已知限制

没有语义判停模型（豆包有标点预测），只能靠固定观察窗近似：说到一半停两秒以上仍会被切开。
