# ADR-0007：多路模型路由故障切换与降级运行

- 状态：`DRAFT` / `NOT_APPROVED` / `NOT_VERIFIED`
- 日期：2026-10-18
- 触发事件：v4 24 小时常驻运行在 elapsed 5140s 中断（`HTTP 402 insufficient_quota`）
- 关联：INV-010（取消—发布线性化之外的独立不变量，见 ADR-0006）、unknown-gate 语义、`packaging/product_config.py`、`packaging/soak/run_soak.py`
- 裁决权：核心供给语义变更，需 Sir 批准后方可实现；本文件只描述方案

## 1. 背景与实测事实

2026-10-18 06:10，v4 常驻运行对 `api.aicoming.top` 的调用开始全部返回：

```
HTTP 402 {"error":{"message":"insufficient balance","type":"insufficient_quota"}}
```

`gpt-6.1-sol-official` 与 `gpt-6.1-sol` 均 402；宿主 Hermes 与产品用的是同一把 key（SHA-256 前 16 位一致）。

产品层表现：

| 层 | 观测 |
|---|---|
| `soak_model_calls` | 82 条 `completed` 停在 06:10:08，之后 7 条 `dispatched_unknown`（06:10:49 … 06:30:21） |
| `model_failure_backoff` | `failures=7`，`next_at` 已推到 300s 档 |
| `samples.jsonl` | `thoughts` 恒为 127，`pending` 持续增长（1483 → 1531） |
| 代码行为 | unknown-gate 表现正确：无全局冻结、身份不重发、退避递增、预算照扣 |

结论：**代码没有回归，是单点供给断了，而产品没有任何应对单点供给断掉的机制。**

当前配置是封闭字段集：

```python
CONFIG_FIELDS = frozenset(
    {"model", "provider", "base_url", "api_mode", "context_length", "reasoning_effort"}
)
BINDING_VERSION = 1
```

一个 `base_url` 就是全部供给。它挂掉，整个"住在服务器里的人"就失去认知能力，且无法区分"供应商永久拒付"和"网络一时不通"——两种情况的正确处置完全相反，产品却用同一条 unknown 路径处理。

## 2. 决策

### 2.1 配置：路由列表（schema v2，向后兼容 v1）

`CONFIG_FIELDS` 增加可选字段 `routes`，`BINDING_VERSION` 升到 2。v1 配置（单 `base_url`）继续有效，等价于只有一条路由。

每条路由：

```json
{
  "id": "aicoming-sol",
  "model": "gpt-6.1-sol-official",
  "provider": "custom",
  "base_url": "https://api.aicoming.top/v1",
  "api_mode": "chat_completions",
  "context_length": 256000,
  "reasoning_effort": "high",
  "key_ref": "primary"
}
```

`key_ref` 只指向既有 key-file/FD 通道里的凭据槽位。**密钥仍不得内联进配置、argv、环境变量或日志**——这条边界不因本 ADR 放宽。

路由按数组顺序作为优先级。只有熔断器处于闭合（closed）状态的路由才可选。

### 2.2 单次调用只走一条路由

一次模型调用在选定路由后，整次调用绑定该路由，不做调用中途切换。因此一条 call identity 永远对应"一条路由 + 一次尝试"，审计可逐条归因到具体供给。

### 2.3 失败分类（本 ADR 的核心）

| 分类 | 判据 | 调用状态 | 预算 | 身份 |
|---|---|---|---|---|
| `DEFINITIVE_REJECT` | 4xx 中在生成开始前就被拒绝的：400/401/402/403/404/409/422 | `failed_definitive`（新状态） | **退还**（未消耗 token） | 逻辑意图可用**新** identity 换路由重派 |
| `TRANSIENT` | 408/429/5xx、连接重置、响应前超时 | `dispatched_unknown`（沿用） | **不退还**（沿用） | 同一 identity **永不重发**（沿用） |
| `SUCCESS` | 200 且正文可解析 | `completed` | 照常扣减 | — |

关键判断：unknown-gate 的"身份不重发"是为了防止**可能已发生的副作用被重复执行**。而 `DEFINITIVE_REJECT` 是已关闭、零副作用的结果——请求在生成前就被拒绝，没有产生任何回复。因此换路由重派**不是**重复副作用，是首次有效尝试。这条区分必须由机器断言强制，不能靠注释。

### 2.4 熔断器（按路由独立）

- `DEFINITIVE_REJECT` 且属认证/配额类（401/402/403）→ 立即开路，冷却 1800s 或直到配置重载。此类错误重试无意义，立刻换路。
- `TRANSIENT` → 连续 3 次开路，300s 后进入半开，放一次探针；探针成功闭合。
- 熔断状态持久化，重启不丢。

### 2.5 降级运行（全部路由开路时）

- 持久化 `degraded_since`，daemon 心跳照常，**不再发起模型调用、不空转、不刷 unknown**。
- 每个降级周期只向 Sir 通知一次，走既有本地 outreach 草稿通道；不外发邮件/iMessage（该边界属于运行时投递策略，不在本 ADR 扩展）。
- 首个探针成功后退出降级，恢复常态。

### 2.6 可观测性

`soak_model_calls` 增加两列：`route_id`、`failure_class`。采样计数器增加按路由的成功/失败/unknown 分项。任何一条念头都必须能回答"这是哪条路由、哪个模型产出的"。

## 3. 验收方案（不需要第二个真实供应商）

用受控 HTTP 假服务，两条路由：

- 路由 A：恒返回 402
- 路由 B：返回合法补全

必须证明四件事：

1. **切换**：A 拒付后，同一轮内 B 接手，认知继续（thoughts 增长），不是靠等待。
2. **归因**：该轮念头记录 `route_id=B`；A 的调用记录为 `failed_definitive` 且预算已退还。
3. **全断**：A、B 均 402 时进入降级，identity 数量不因重试而膨胀，心跳不断。
4. **不误判**：A 超时（响应前）时仍是 `dispatched_unknown`，identity 不重发、预算不退——不能因为引入了 failover 就把 unknown 语义放宽。

以上四条全部为机器断言，可复跑。

## 4. 明确不做的

- **不静默降级模型档位**。换到不同模型就是行为变化，必须逐条记录 `route_id`，并由 Sir 裁决人格/语气相关的通道是否允许跨模型切换。
- 不做"把同一个 identity 重发到另一路由"的通用重试。只允许在 `failed_definitive` 已持久关闭之后，以新 identity 重派。
- 不在本 ADR 里改宿主 Hermes 的模型路由；这只约束 JARVIS 产品自身。
- 不在常驻运行期间改 `packaging/`。本文件落盘期间 main 仍被 v4 的冻结哈希覆盖，实现必须等本轮运行结束。

## 5. 未决项与建议默认值

以下四项属产品语义，最终由 Sir 裁决；在得到否决前，实现按"建议默认值"推进，并逐条记录在案，便于随时回退。

- **U-1 人格/语气关键通道是否允许跨模型切换？**
  建议默认：允许，但受两条约束——① 每条念头必须记录 `route_id`，事后可追；② 同一条对话线程内不跨模型，避免同一个"人"在几轮之内换说话方式。人格一致性优先于可用性，但完全不可用比换模型更糟。
- **U-2 `DEFINITIVE_REJECT` 退还预算是否会让"预算耗尽"保护失效？**
  建议默认：退还只发生在"生成开始前被拒绝"这一可判定条件下（响应体不含任何补全内容、且 HTTP 状态属 4xx 白名单）。一旦有响应正文，一律按已消耗处理。
- **U-3 降级期是否用本地模型维持最低限度内心活动？**
  建议默认：不用。本机当前没有常驻本地模型，降级期保持心跳与状态持久化、完全静止，不制造"还在思考"的假象。要维持最低活动，先单独裁决本地模型的引入。
- **U-4 401/403（密钥失效/无权限）与 402（欠费）是否同冷却期？**
  建议默认：不同。401/403 是配置或权限错误，换路由无用，直接停并通知 Sir；402 是余额问题，冷却 1800s 后探针重试，期间其余路由可用。

## 6. 本轮已落地的周边修复（不改 `packaging/`）

在 v4 中断后，宿主侧自动化补了三处，均已实测：

1. **余额看护**（`jarvis_balance_watchdog.py`，cron 每 10 分钟）：空档 ≥3600s 且余额未恢复 → 停 v4、记录、通知；余额恢复且 v4 已停 → 自动起 v5 并通知。已用桩件验证三条分支（停、静默、重启）。
2. **凭据生命周期**：v4 后处理原会在运行结束即删凭据，会让自动重启必然失败。已改为"重启待定则保留"，并由 v5 后处理在收尾时删除；v4 停止超 24h 仍未充值则过期清理。三种情形均已实测。
3. **进程匹配**：后处理脚本的 `pgrep` 原先只匹配 `run_soak.*86400`，v5 起跑后会被误判成 v4 仍在运行。已改为匹配各自 evidence 目录。

## 7. 实测数据：廉价备用模型能否承担验收语义（U-1 的决策依据）

2026-10-18 06:40 起，用 `deepseek-v4.1-flash`（备用路由 B）起了一条 12 小时连续性运行，代码与提示词与主路线完全同一份冻结快照（4784 文件同哈希）。同一套严格 schema 下，两条路线的模型输出质量差异如下（数据取自各自 `mind.db` 的 `model_response` / `validation_error` 条目）：

| | 主路线 gpt-6.1-sol-official | 备用路由 B deepseek-v4.1-flash | 备用路由 C qwen-plus |
|---|---:|---:|---:|
| 真实运行：模型响应 | 82 | 40 | 4 |
| 真实运行：校验失败 | 1 | 32 | 4 |
| 真实运行：失败率 | **1.2%** | **80%** | **100%** |
| 真实运行：已接受念头 | 127 | 29 | 0 |
| 隔离探针（`route_compliance_probe.py`） | 未测（402） | 13/18 = 72% | 26/26 = 100% |

**两条备用路线都不合格，而且隔离探针不能预测真实表现。** 探针用产品自己的校验器，但它给的上下文比真实运行薄：没有完整 `INSTRUCTIONS + CURIOSITY_INSTRUCTIONS`，没有真实信念 id、候选、事件、记忆、未决疑问，也不跑后续的 `validate_matrix`。deepseek 探针 72% 而真实 20% 通过；qwen 探针 100% 而真实 0% 通过。

已排除一个看似合理的解释：不是"同一响应内引用较早念头被拒"。代码 `inner_runtime.py:274-275` 在每条念头通过后把它的 id 加入 `known`，实跑验证 `t2→t1` 合法、`t1→t3` 被拒；主路由 44 条带 `t1` 引用的念头全部通过。真实原因未定，登记在 `docs/reports/OPEN_20261018_QWEN_PASSES_PROBE_FAILS_LIVE.md`。

失败分类（路由 B，逐个回读原始文本判定）：

- **JSON 语法破损 2 例**：一例 `Expecting property name enclosed in double quotes`（第 1836 字符），一例 `Expecting ',' delimiter`（第 1447 字符）。都是模型自己产出的花括号/引号错误，不是传输截断——文本长度 2728 / 1660 字符，尾部完整闭合。
- **缺必需字段 1 例**：响应只有 `relevance / thoughts / scheduler_question / resolved_questions`，没有 `knowledge_gaps`，触发 `KeyError`。
- **语义校验失败 4 例**：JSON 可解析、字段齐全、内容看起来合理（例如「本次样本采样于 19:32:38Z，作为工具结果在 22:42:48Z 到达，滞后约 3 小时 10 分；仅为单次观测」），仍被拒。具体断言未逐条定位到源码行；候选是 `curiosity.validate_matrix` 的 `Incomplete relevance matrix`（relevance 矩阵未覆盖全部合格信念×能力）与 `validate_gaps` 的字段集校验。

**同时必须说清的正面证据**：路由 B 已通过的念头质量不低。原文一例——「这条 activitywatch 结果里只有 status: available、采样时间 19:32:38 和 precision 标签，没有任何应用名、时长或窗口标题。所以它证明的是通道通着，并非『我看到了 Sir 在做什么』。这种空载荷的心跳如果被当成观测记进账本，会污染后面所有推断——它只能算传感器自检。」这条判断是对的，而且指出了采样链路的一个真实缺陷。

**结论（供 U-1 裁决）**：

1. 廉价模型**能**维持认知循环活着，输出不是废的；
2. 但它**不能**承担验收语义——近六成输出过不了同一套 schema，且失败集中在结构化纪律（闭合括号、字段完整、矩阵覆盖），不是理解力；
3. 因此 failover 的设计不能是「换到任何一条能通的路线」，必须是**经过 schema 合规性验证的路由池**；新路由入池前要先跑一批真实调用测合规率，达标才允许接主通道。

据此把 U-1 的建议默认值收紧为：跨模型切换**允许但受门禁约束**，而且门禁不能用隔离探针——必须跑一段带完整上下文的短常驻（跨过冷启动、上下文里已有念头），看真实拒绝率，门槛建议 ≥95%（主路线实测 98.8%）。每条念头记录 `route_id`；同一条对话线程内不跨模型。

一条更硬的结论：**这套 schema 目前只有强模型能稳定满足**。本机现有的两条廉价供给（deepseek-v4.1-flash、qwen-plus）实测都不合格，所以 ADR 里的 failover 若只接到廉价模型上，等于没有 failover。真要做供给冗余，需要第二条**同级别**的强模型线路，而不是"能通就行"的兜底。
