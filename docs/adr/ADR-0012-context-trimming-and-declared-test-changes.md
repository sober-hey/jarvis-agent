# ADR-0012 上下文裁剪保留「时钟锚点」与「等 Sir 回答的缺口」，并申报三处测试语义变化

状态：已实施（2026-10-21），**A6 验收仍未通过**，此改动不得计入"已验收"
相关：`packaging/inner_runtime.py`（裁剪顺序）、`packaging/replay_quota.py`（配额保留）
来源：评审整改项 P0-4 与 P1-6（`docs/reports/REVIEW_20261021.md`）

## 背景

上一版裁剪按"最大的列表先砍"，会先砍掉两类不该砍的东西：

1. **本轮时钟事件**：模型没有 `now` 就无法产生有依据的念头，只能输出无锚点的空想。
2. **已有问题在等 Sir 回答（awaiting_sir）**：把它裁掉后，模型看不到"已经问过"，会重复提问。

评审指出这两处改动（168 行）在提交说明里未申报，且 A6 的原验收记录仍为 NOT_PASSED。

## 决策

裁剪顺序改为：

1. 时钟锚点（`kind=time` 的那条事件）最后才动；若只剩它，`clock_only()` 保护它不被选中。
2. `awaiting_sir` 的缺口属于"未结状态"，不是历史：普通 beliefs 先走，之后才动它们，
   且排在其后的还有过期相关性缓存与未用能力元数据。
3. 语义是"少砍"，不是"多砍"——不新增任何内容进上下文，只调整删除优先级。

## 申报：三处被判定为语义变化的测试改动

这三条不是"陈旧断言"，是产品行为的确切变化，单独列出以便复核：

| 测试 | 原断言 | 现断言 | 为什么 |
|---|---|---|---|
| `test_switch_model.py` | 只接受精确的 provider 串 | 至少命中一个已声明 provider | 配置里 provider 允许别名与 custom: 前缀，精确比较会把等价写法判错 |
| `test_curiosity.py`（KnowledgeGap） | 有活源时必须先 execute | 保留 execute，但不再要求"必须在同一 tick 饿死其它 gap" | 与 A6 的调度语义冲突；原断言把一种实现顺序当成了契约 |
| `test_inner_model.py` | 禁止出现 `model_attempts` | 允许该字段 | 它是既有产品字段（调用的尝试记录），禁止它等于禁止审计痕迹 |

## 未完成

A6 的原验收门槛（召回全绿 0/90 → 88/90、validate 差 1 行）**未重跑**。
在重跑 acceptance 并给出结论前，本 ADR 只表示"改动意图与范围已申报"，不表示验收通过。
