# ADR 身份与 Master Plan 主题映射

本表仅消除引用歧义，不修改 ADR 决策，不授予批准。现有文件的 ADR-000x 身份保留；Master Plan §47 的 ADR-00x 为规划中的建议编号。

| 现有 ADR | 主题 | 规划建议编号 |
|---|---|---|
| ADR-0001 | 单执行器 flock / Epoch | ADR-009 |
| ADR-0002 | Prepared / Intent 顺序 | ADR-006（部分覆盖） |
| ADR-0003 | 快照一致性 | ADR-005 |
| ADR-0004 | 原子不覆盖发布 | ADR-007；ADR-008 耐久性仍需单独记录 |

| ADR-0006 | 取消—发布并发线性化 | 无对应规划编号；规划 ADR-006（Prepared/Intent 顺序）仅部分相邻，不得混用 |
| ADR-0007 | 多路模型路由故障切换与降级运行 | 无对应规划编号；规划中「模型供应商」主题 |

| ADR-0008 | 语音合成改用火山 seed-tts-2.0 | 无对应规划编号；语音供给（已实施） |
| ADR-0009 | 一句话切分放客户端（UtteranceGate） | 无对应规划编号；语音交互（已实施） |

| ADR-0011 | 结果未知默认拒绝新发送 | 与 ADR-0001/0006 相关，不替代它们（已实施） |

ADR-0006 为 2026-10-18 新增草案（DRAFT / NOT_APPROVED），承载 DEC-004 / FS-047(O-4) / RECOVERY OPEN-01 的证明义务形式化；它不关闭上述任一项，也不代表 INV-010 成立。

ADR-0007 为 2026-10-18 新增草案（DRAFT / NOT_APPROVED），因 v4 常驻运行实测被 `HTTP 402 insufficient_quota` 单点中断而提出。它不改现有供给语义，U-1..U-4 待 Sir 裁决；实现须等本轮常驻运行结束（main 的 `packaging/` 仍在冻结哈希覆盖下）。

规划中的仓库位置、Python、Schema、安全 API、launchd、模型供应商、审批、预算与 K4 隔离主题尚无独立正式 ADR；按相关任务补齐。仓库位置与 Python 基线已由用户指令和环境事实明确；该事实不构成对其他安全 ADR 的批准。

引用时使用现有完整文件名和主题，禁止仅凭数字推断主题。所有现有 ADR 仍保持原状态。
