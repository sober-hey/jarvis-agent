## 3. 候选方案（PROPOSED；代价逐条列"违反/偏离"，本表不得作为 C1′ 优于 C2 的依据）

| ID | 形态 | 预防能力 | 违反/偏离（读法前提须写明） |
|---|---|---|---|
| C1′ | 独立仲裁锁只跨 FS（取消/stop 检查→`mkdir`→`link`→目录同步）；DB 两段短事务（锁内短读 → `link` → 短写） | 机制上可预防，前提 A1–A6（**全部未证**） | 偏离 §14/FS-032 **步骤 13**（Attempt 在 `link` 之后）；把事务原子性换成"锁互斥＋两步非原子记录"，跨资源非原子边界更暴露（§4.1 L276–277） |
| C2 | 不新增锁，用写事务互斥（`BEGIN IMMEDIATE` 跨 `link` 至提交） | 机制上可预防 | 违反 §10 L826–827；**若同一事务承载 Intent 则同时违反 §14.1 L1497–1499／FS-033／INV-002（L254）**；若 Intent 已提前提交，仍偏离步骤 13/15/16 |
| C3 | 纯 DB CAS 令牌 | **不能**（`link` 在 DB 外，窗口无界，只能事后检测） | 只可作审计补充 |

- **C1′ 协议草案（候选，非规范）**：前置在临界区**之前**完成——Intent＋FileWriteIntent 已按 §14 步骤 7–12 提交成功、Prepared 达 DURABLE_PREPARED；Attempt（步骤 13）位置**待裁定**（§6 第 2 项）。发布方＝①取仲裁锁（覆盖 检查→`mkdir`→`link`→目录同步 全程，期间不等外部输入）；②锁内**新建**短读事务读 `cancel_requested_at_ms`/stop/`worker_epoch`/所有权，读完立即结束；③事务外 `mkdir`（如需）＋`os.link`＋目录同步；④`link` 之后的独立短写事务提交状态与事件（**MUST 带 `worker_epoch`/所有权 CAS**，§17.2 L1824–1826、INV-009），`COMMIT` 返回后释放锁。取消/stop 写入口＝同一把锁、短写事务、`COMMIT` 返回后才释放。
- **全序论证（草稿，未证）**：P1 两临界区互斥；P2 `L_cancel` 在取消方临界区内；P3 `S_link` 在发布方临界区内；P4 发布方的取消判定为获锁后**新建**快照。⇒ 两临界区构成全序；若 `L_cancel < S_link` 而发布方先，则发布方须先获锁并在其临界区内完成 `link` 后才释放 ⇒ `S_link < L_cancel`，矛盾 ⇒ 发布方获锁时取消已提交、其首读必见 ⇒ 按 §9.1 L746 不得 `link`。**不依赖锁公平性，不以 wall clock 判定。**
- **A1（无旁路）** 候选旁路清单（**推导清单，非穷举证明**）：§15.3 L1591 首发布；§18.2 L1924 安全重试；§16.3 L1744 `RETRY_SAFE` 重发；§18.1 L1885–1915 恢复流程内的发布点；取消核对本身为只读。任一清单外路径产生目标副作用 ⇒ **A1 失效 ⇒ 不得主张 INV-010**。
- **A2（锁身份）** 路径固定、两方一致（§17.1 第 5 条 L1802）、运行中不删除（第 4 条 L1801）；"取锁前校验锁 fd `(dev,ino)` 与路径一致"与"锁文件路径/所在卷"均为**本提案新增且未定**（§17.1 的规范对象是 `worker.lock`，L1805–1808）。
- **A2 延伸（OPEN，不自定）**：每个参与方必须**各自独立 `open` 锁文件**（各持自己的 fd）；flock 与"打开文件描述"关联——**同一 fd 上的重复 flock 不产生新的互斥**，故同一进程内的多线程必须另有**线程级互斥**，否则互斥不成立。该语义与本机实现方式均未验证，**探针前不得主张同进程安全**。
- **A3** 目标卷（含外接硬盘）上 flock 排他、进程终止自动释放成立——**依据是 ADR-0001**（`Status: PROPOSED`，验证要求含"双进程竞争、异常退出…"，冻结条件含真实平台测试与人工批准）；**DEC-003 只确认文件系统能力清单，不构成 flock 语义依据**；须探针。**A4** 单主机、单执行器、`worker_epoch` 有效（INV-008/009＝L260/L261）。
- **A5（协议层义务）** 检查读必须是获锁后新建事务；写方 `COMMIT` 返回后才释放锁——"夹具以标记校验"只能验证**桩自身**次序，**不能**验证产品代码（FREEZE_PROPOSAL C10 L210）；`L_cancel` 与释放的先后需桩内标记/共享屏障，不能靠跨进程时钟比较。
- **A6（SQLite WAL 平台语义，须探针/权威文档）** "事务首读见到该时点已提交状态"与"COMMIT 成功返回 ⇒ 已持久且对其后**新建**事务可见"；本仓库唯一数值来源 §10 L810–822（WAL／`synchronous=FULL`／`busy_timeout`）。
- **锁层次（OPEN，不自定）**：发布方即执行器并按 §17.1 第 3 条 L1800 长期持有 `worker.lock`，"持 `worker.lock`→取仲裁锁"必然存在；**禁止**任何"持仲裁锁→等 `worker.lock`"的反向顺序（否则无界等待/死锁）。取消方 MUST NOT 调用执行器接口。
- **哈希复验顺序（待裁定）**：本草案把"验证 Prepared 哈希"放在**取锁前**（辩护：§15.2 L1589"发布前 Prepared 不再允许正常修改"），与 FS-042 L63／§15.3 L1596→L1600 的字面顺序不同；不接受则须改回锁内。
- 已搁置的替代：取消走 IPC 交给执行器（执行器不存活时取消无法提交→不可接受）；"发布窗口标志＋取消方等待"（会引入自旋/超时活性问题，非"无证明力"）。

## 4. 崩溃、失败与未知结果（候选处置；批准前不构成规则）

| 场景 | 候选处置 |
|---|---|
| 发布方在 `link` 前崩溃 | 锁随 fd 释放；无副作用；取消流程正常持久化 |
| 发布方在 `link` 后、步骤④提交前崩溃 | 副作用可能已发生、记录未知：只读观察（§16.1）；MUST NOT 未核对即判"无副作用 CANCELED"；禁止删/改名目标（§15.4）；`TARGET_ABSENT` 不等于"从未执行"（L1688） |
| **`link` 成功、步骤④提交失败（BUSY/IO，非崩溃）** | 同上：不重试（INV-005＝L257）、不删改目标、只读观察、上报未知/BLOCK 待人工；禁止用默认值补全 |
| **`link` 已成功、目标目录同步失败** | 副作用**已经发生**，MUST NOT 称"未执行／未发布"：只读观察目标（§16.1）；**按 FS-063 阻断进入生产等级**（拒绝执行，不得降级放行）；进入 Reconcile（§16）；禁止删/改名目标 |
| 取消方在 `COMMIT` 返回前被 kill | 持久化状态**未知**，MUST NOT 断言"从未持久化"。重启后**权威读**判定，须同时满足：WAL 恢复已完成、读取**本身成功**（非 BUSY/IO/权限异常）、读的是权威当前库；任一不满足 ⇒ `INSUFFICIENT_EVIDENCE → BLOCK`，**不得**据此 `link`；三条满足且读不到 ⇒ 取消未提交、INV-010 不适用 |
| `kill -9` 场景的对外口径 | 被信号终止的进程**不产生退出码**，"命令 MUST 返回非零"不可执行：改为**对调用方**的要求——非正常终止不得被解释为取消成功，结论以重启后权威读为准 |
| 锁不可得／超时／不支持 flock／DB 不可读 | 发布方 fail-closed：MUST NOT `link`；**超时不得被当作锁已释放**；上界与升级路径见 §6 第 3 项 |
| 紧急停止（stop） | stop 必须持久化且禁止新目标副作用（§9.3 L785–788、INV-011＝L263），与"stop 写入口同锁"在慢速卷上可能冲突（stop 无法及时持久化）。**该冲突为 OPEN**：候选出路①stop 写入不受仲裁锁阻塞（须登记为 A1 的**显式例外**并重估 A1）、②另行定义优先序——**均需裁定，本文件不自定** |
| 任何未知结果 | 不 `link`、不重试、上报 BLOCK/人工；禁止用超时、默认值或模型推断补全（§16.2/§16.4） |

- **不主张跨资源原子性**：不把 SQLite 事务与 FS `link` 合并为原子操作，不主张通用 exactly-once（§4.1 L276–277）。K0 承诺限于"单一目标＋单一发布点＋可观察核对"，副作用以观察与哈希为事实（§16.1/§16.3），不靠回滚撤销。
- 取消之后：§16.3 L1744 的 `TARGET_ABSENT → RETRY_SAFE` 前提含"未取消、未停止"，故取消已提交时 MUST NOT 重试发布；残留 Prepared 按孤儿规则处理（§18.3）。

## 5. 夹具与竞态计划（本文不实现；夹具结论 ≠ 产品结论，FREEZE_PROPOSAL C10 L210）

- 边界：受控临时目录（目标卷，至少一次真实外接硬盘）＋测试库（WAL／`synchronous=FULL`／`busy_timeout=5000`，§10 L810–822）＋一份 Prepared＋一个固定 `target_relpath`＋两个进程桩。
- 交错：禁止 sleep 判胜负；用 FIFO/文件屏障/夹具专用钩子打标记（钩子不进产品代码）；跨进程先后以**锁顺序/屏障标记**为准，单调时钟不跨进程比较。

| 用例 | 通过判据 |
|---|---|
| F1 取消先 | target 不存在且由**钩子级证据**证明无 `link`；取消已持久化；无发布事件；发布方检查读发生在获锁之后 |
| F2 发布先 | target 存在且哈希符合；取消核对得 `EXPECTED_EFFECT_PRESENT`；副作用保留在记录中；无自动重试 |
| F3 P 在 `link` 后／提交前 `kill -9` | target 在、库内无发布记录；核对输出"已发生副作用"；不删除 target |
| F4 C 在锁内／`COMMIT` 返回前 `kill -9` | 锁自动释放；重启后**权威读**判定并分支（有取消 ⇒ P 不得 `link`；无取消 ⇒ P 可继续）；调用方结论＝非正常终止≠成功 |
| F5 锁不可得 | P fail-closed（无 `link`）；C 不报告成功；状态可解释 |
| F6 stop×cancel 并发 | 任一写入顺序都不出现"检查通过后仍 `link`"（须在 §6 第 3 项 stop 冲突裁定之后才可作此断言） |

| F8 `link` 成功／短写失败 | 目标保留（不删、不改名）、不得重试、只读观察并上报未知/BLOCK；库与桩记录一致（与 F3 的崩溃支路区分：非崩溃、进程存活） |
